WHAT THIS IS
A small working demonstration of your approved-direction TimeTableX idea:
sample data -> constraint checks -> recursive search -> validation -> timetable.
It follows the CLI-first approach in your proposal and personal guide.
The scheduling engine is handwritten C++; no external libraries are needed.

RUN ON WINDOWS
1. Extract the entire ZIP.
2. If g++ is already installed and on PATH, double-click run_windows.bat.
3. Choose 1 to generate the timetable. Open timetable.csv in Excel if desired.
4. Choose 2 for an impossible case, or 3 to run the nine checks.
5. Choose 0 to exit.
The batch file needs a C++ compiler; it is not a precompiled Windows program.

FIRST TWO-MINUTE DEMO
Choose 1. You will see eight sessions automatically assigned to times and rooms.
Teacher A cannot teach Sunday 09:00. Two independent classes may run at once,
but the same teacher, batch, or room cannot be double-booked.
See the full timetable and the two batch views. The output reports zero hard
violations after an independent validator checks the completed assignments.
Choose 2. Teacher A now has no available periods, so generation fails cleanly.
This case does not overwrite the CSV from your previous successful run.
Choose 3. Nine checks include a forced backtracking example.

WHAT TO READ IN main.cpp
1. Session and Placement: small structs, similar to C structs.
2. sample(): the data; every row means one required one-hour class.
3. canPlace(): checks availability and teacher/batch/room collisions.
4. search(): try a position, recurse, undo it if later classes cannot fit.
5. validate(): checks the whole result independently of canPlace().
6. show() and exportCSV(): present the computed result.
7. main(): simple terminal menu.

TRY A SMALL CHANGE
In sample(), change p.available[0][0] = false to another slot index.
Indices 0,1,2 are Sunday 09:00,10:00,11:00; 3,4,5 are Monday, and so on.
Add a repeated session row to request one more class, then rebuild.
Teacher IDs are 0..2, batch IDs 0..1. Keep IDs within those ranges.
This tiny version assumes trusted, valid built-in data; it has no input editor.

WHY CLASSES MAY CLUSTER EARLY IN THE WEEK
The search tries early slots first and stops at the first valid timetable.
Repeated courses may be placed on the same day. This is allowed in this beta.
A valid timetable is not necessarily convenient: soft scoring and optimization
are planned later. The normal demo may need zero backtracks; the forced test
proves the undo-and-retry path also works.
